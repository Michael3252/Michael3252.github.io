## 시각적 콘셉트

사용자는 로봇 그림의 뇌에 AI, 심장에 Physical AI를 연결하는 아이디어를 제안했다. 이를 보조 탐색 도식으로 사용한다.

- 뇌: 인식, 예측과 AI 응용
- 심장: 로봇 실행, 좌표 변환과 제어
- 로봇이 든 화면 또는 별도의 서비스 연결점: 웹서비스와 데이터 활용

도식을 클릭하거나 탭하면 해당 경험으로 이동한다. 로봇을 조작하지 않아도 일반 메뉴, 본문과 프로젝트 링크로 모든 내용을 읽을 수 있어야 한다. 모바일에서는 도식을 간소화하고 일반 링크를 함께 제공한다.

첫 화면의 약 3분의 2는 이름, 소개와 이력 요약, 나머지는 도식에 사용한다. 전체 화면을 로봇으로 채우는 탐색형 첫 화면은 채용 목적에 맞지 않는다.

## 페이지 구성

| 경로 | 역할 | 주요 내용 |

## 상세 페이지의 구성

첫 문단에 어떤 문제를 해결하는 프로젝트인지 설명한다. 기간과 형태는 기록이 있을 때만 적고 본인 역할을 바로 이어 보여준다.

본문은 해결하려던 문제, 본인의 판단과 구현, 전체 흐름에서 담당한 구간, 결과와 검증 순서로 구성한다. 기술 로고만 나열하지 않고 실제 사용 맥락을 적는다. 프로젝트의 팀 결과와 본인의 구현은 별도로 표현한다.

원본 화면과 사진, 영상에는 설명을 붙인다. 삼성 화면은 가상 데이터 예시임을 표시한다. UMI 모델은 실행 구조 설명용 3D 모델로 표시하고 관절, 그리퍼와 끝단 좌표계를 설명한다.

## 디자인 방향

이전 대화에서 제안하고 구현에 착수한 방향은 밝은 배경, 네이비 계열 글자와 차분한 파란색 강조다. 첫 구현에서는 한국어 Noto Sans KR, 영문 Manrope를 선택했으나 최종 화면은 아직 없다. 초기 제안에 있던 Pretendard도 가독성에 맞게 선택할 수 있다. 폰트 자체의 재선정에 사용자 재승인을 요구할 필요는 없다.

- 본문은 16~18px를 기준으로 한다.
- 긴 문장의 폭을 제한하고 제목, 본문, 보조 정보의 차이를 명확히 한다.
- 정보 그룹 사이에 충분한 여백을 둔다.
- 실제 서비스 화면과 프로젝트 자료가 시각적 중심이 된다.
- 자동 재생 영상, 과한 3D 효과와 반복적인 스크롤 애니메이션을 피한다.
- 모바일, 키보드 탐색, 포커스 표시와 모션 감소 설정을 지원한다.

## 기술 구성

Astro와 TypeScript로 정적 페이지를 만든다. GitHub Pages 저장소 이름이 사용자 사이트 형태이므로 루트 경로를 기준으로 빌드한다. 서버 로그인이나 데이터베이스는 이 포트폴리오 자체에 필요하지 않다.

- 학력과 프로젝트 메타데이터는 구조화한 데이터로 관리한다.
- 상세 글은 Markdown 또는 구조화한 콘텐츠로 관리한다.
- 영상과 3D 모델은 사용자가 상세 페이지에서 요청할 때 불러오는 방식을 우선한다.
- 이미지 크기를 고정해 로딩 중 레이아웃 이동을 줄인다.
- 실제 SO-ARM101 모델은 필요하면 GLB로 변환해 Three.js로 보여준다. 정적 대표 이미지를 함께 제공한다.
- GitHub Actions에서 검사와 정적 빌드 후 GitHub Pages 배포를 구성한다.
- SEO 제목, 설명, OG 이미지, 사이트맵, robots.txt와 404를 포함한다.

## 구현 후 검증

데스크톱과 모바일에서 실제 화면을 확인한다. 프로젝트 필터, 메뉴와 상세 링크, 이메일, 영상 재생, 3D 불러오기와 초기화, 이력서 인쇄가 동작해야 한다. 누락 이미지와 잘못된 경로, 가로 넘침, 브라우저 오류를 함께 확인한다.

성능과 접근성은 실제 검사 결과로 설명한다. 아직 빌드, 테스트, 브라우저 QA와 배포는 수행하지 않았다.
