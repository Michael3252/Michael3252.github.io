팀의 인터페이스 변경 전달 문제와 AI로 개발한 프로그램의 전체 구조를 이해하기 어려운 상황에 대응한 협업 웹서비스다. 시스템 구성 요소와 통신 규칙을 캔버스에 표현하고, JSON 가져오기와 내보내기로 사람과 외부 AI가 같은 설계 정보를 활용하도록 했다.

HTML, CSS, JavaScript ES Modules로 프런트엔드를 구현했고 Node.js, Fastify, SQLite와 WebSocket을 사용했다. 객체별 잠금과 접근 권한, 편집 상태 동기화를 구성했다. GitHub App으로 브랜치 생성과 PR 등록을 연결했다. Docker와 GitHub Actions를 이용해 AWS에 배포했다.

사용자 피드백을 받아 객체별 띠지와 파일 확장자 아이콘을 추가하고, 핵심 정보와 세부 설정의 노출을 나눴다. 서비스 내부에서 LLM이나 자율 에이전트를 실행하는 구조로 표현하지 않는다. React 또는 TypeScript를 사용한 서비스로 바꾸어 적지 않는다.

## SW 품질 관리 업무 지원 플랫폼

- 참여: 삼성청년SW·AI아카데미 기업연계 프로젝트, 삼성전자 네트워크사업부, 디지털시티
- 인원: 6인 개발팀
- 기간 기록: 2026.10.07부터 참여, 기존 종료 계획 2026.11.18. 완료를 별도로 확인한 기록은 없다. 종료 실적이 필요 없는 화면에서는 2026.10부터 참여로 표현한다.

여러 검증 업무 플랫폼의 데이터를 활용해 검증 계획과 일정을 관리하는 EM의 판단을 돕는 플랫폼이다.

본인은 기능 담당자들이 필요한 컬럼을 조사하고 중복 항목을 정리해 공통 DB를 구축했다. 사업자, Feature, TC와 연관 테이블을 외래 키로 연결했다.

처음에는 기능별 시험 실패 건수로 위험도를 안내했으나 현업 반응을 보고 업무를 관찰하고 미팅했다. 다른 프로젝트의 동일 기능 검증 결과를 활용하는 인용 절차를 파악하고, 공통 기능의 검증 현황을 비교하는 기능으로 전환해 제안하고 구현했다. 인용 결정과 관련 부서 탐색에 도움이 된다는 평가를 받았다.

또한 Python FastMCP로 검증 업무 플랫폼과 Confluence를 연결하고 API와 데이터 설명을 지식문서로 제공했다. 사내망 LLM을 이용하는 Cline 환경에서 조회한 자료를 사용자 요청에 맞게 정리하는 흐름이다.

에이전트가 프로젝트 범위, 결함 상태와 조회 기간을 임의로 정하는 문제에 대응해 FormHost 스킬을 구현했다. 질문 JSON을 MCP로 전달하면 로컬 설문 웹을 제공하고 Chromium 창을 열어 응답을 받는다. 기간, 프로젝트와 상태를 선택하고 응답을 Cline이 읽도록 연결한 뒤, 해당 테스트에서 의도에 맞는 결과를 얻었다.

소개할 흐름은 사용자 요청 → FormHost 조건 선택 → MCP 데이터 조회 → 표, 그래프와 문서 정리다. 자동화율, 시간 단축률이나 전체 요청 정확도를 만들지 않는다. 일정 관리와 모든 팀 화면을 본인이 단독 구현했다고 표현하지 않는다.

제공된 HTML 4개와 폼 이미지의 업무 데이터는 사용자가 페이크 데이터라고 확인했고 모두 공개를 허용했다. 삼성 로고 앞 단체사진도 이 프로젝트의 자료다.

실제 항공영상, 마스크, 연결요소 이미지와 방법론 원본이 있다.

## UMI 기반 로봇팔 학습 플랫폼

SO-ARM101과 UMI 핸들의 URDF를 이용해 MuJoCo 환경을 구성했다. 목표 물체를 무작위 위치에 생성하고 일정한 위치로 옮기는 동작 데이터와 가상 카메라 영상을 수집했다. ArUco 전처리, 매핑과 ORB-SLAM3 처리, 학습 데이터 구성과 Diffusion Policy 학습까지 Stanford UMI 파이프라인을 검증했다.

실제 로봇에는 Jetson Orin Nano와 Python 실행기를 사용했다. 본인의 실행기 역할은 정책의 상대 TCP 목표를 베이스 좌표계로 변환하고, 5관절 역기구학을 계산하며, 관절각과 그리퍼 폭을 서보 tick으로 변환해 UART로 전송하는 것이다.

```text
모델의 상대 TCP 목표
  → 관측 TCP 기준 좌표 변환
  → 5관절 역기구학
  → 관절과 그리퍼의 절대 목표 tick
  → 관절별 허용 범위 적용
  → UART SYNC_WRITE 전송
  → 실제 상태 재관측
```

서보의 관절별 PID 게인을 조정하고 부하 테스트로 목표 오차와 떨림 감소를 확인했다. 서보 내부 PID 제어기 자체를 구현했다는 의미는 아니다. 팔 5자유도와 별도 그리퍼를 팔 6자유도로 표현하지 않는다.

시뮬레이션에서 수집한 데이터와 실제 실행기 체크포인트가 동일하다고 단정하지 않는다. 완전한 자율 집기 성공이나 실물 전이 성능을 만들지 않는다.

사용자는 실물 사진 대신 SO-ARM101 모델링 자료를 쓰는 방향에 동의했다. 공식 모델로 대표 이미지와 관절 설명을 만들고, 필요하면 회전 가능한 3D 보기를 제공한다. 모델은 구조 설명 자료로 표시한다.
